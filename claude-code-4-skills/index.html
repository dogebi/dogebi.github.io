AI 티 나는 화면을 네 번 고친다

화면이 어디서 본 듯하다면, 문제는 대개 네 군데 중 하나입니다. 방향이 없거나, 구조가 안 보이거나, 문장이 늘어지거나, 간격이 흐트러져 있습니다. 네 개의 커뮤니티 스킬이 각각 그 한 곳을 맡습니다. 설치 명령과 프롬프트, 그리고 각 스킬이 하지 않는 일까지 적었습니다.

구조를 설명할 때
Humanizer문장 교정
대비 강조, 극적 결론, 의미 부풀리기를 걷어낸다. 사실과 숫자는 건드리지 않고.
공개 문구 마무리

공식 기능이 아닙니다. 네 가지 모두 커뮤니티 제작 스킬/플러그인이며 Claude Code의 스킬 기능으로 실행됩니다. 설치 전에 저장소 코드와 요청 권한을 읽고, 결과물의 브랜드·사실·동작은 사람이 마지막에 확인하세요.

02

작업 순서

전부 설치할 필요는 없다

이미 만든 사이트를 손본다면 Unslop부터. 다이어그램이나 글만 필요하면 해당 스킬 하나만 써도 됩니다. 순서는 편의일 뿐, 앞 단계를 끝내야 다음이 되는 구조가 아닙니다.

설치 · 프롬프트 · 한계

01

Unslop

이미 만든 화면 점검

audithtml

제품과 고객층을 먼저 본 뒤, 간격 → 색 → 아이콘 → 문구 → 타이포그래피 순서로 개선안을 냅니다. 코드 없이 URL만 있어도 페이지 저장본으로 수정 HTML을 만듭니다.

무엇을 짚나

  • 보라 그라데이션, 과한 광택, 이모지 라벨
  • 근거 없는 최상급과 과장 문구
  • 들쭉날쭉한 간격, 제각각인 아이콘과 글꼴
  • 제품 성격과 무관한 레이아웃

한계

  • 운영 사이트를 직접 고치거나 배포하지 않음 — 결과 HTML을 원본과 비교해 반영
  • 저장본에서 동적 요소가 빠질 수 있음
  • 스토리 영상은 선택 기능이고 Playwright·Chromium(+ffmpeg)이 필요

설치

터미널
claude plugin install unslop --marketplace heydamir/unslop

설치 후 새 세션을 열거나 /reload-plugins를 실행합니다.

실전 프롬프트

프롬프트
/unslop https://example.com
이 사이트를 저장해서 원본 화면을 먼저 살펴봐 줘.
제품의 브랜드와 고객층에 맞는 방향을 제안하고, AI 템플릿처럼 보이는 요소를 위치와 함께 진단해.
간격, 색, 아이콘, 문구, 타이포그래피 순서로 개선하고 별도의 HTML/CSS 결과물을 만들어 줘.
운영 사이트에는 배포하지 말고, 변경점과 저장본에서 보존되지 않을 수 있는 요소를 알려 줘.
02

UI UX Pro Max

제품에 맞는 디자인 기준

directiontokens

“고급스럽게” 대신 업종과 고객층을 말하면, 그에 맞는 첫 화면 구조·색·글꼴 조합과 피할 패턴을 제안합니다. 기존 프로젝트에서는 토큰과 컴포넌트 구조를 먼저 읽습니다.

숫자는 저장소마다 다르다

  • README: 제품 유형 194 · 팔레트 194 · 글꼴 조합 74
  • 릴리스 v2.15.0 노트: 제품 유형 192
  • 기본 브랜치와 배포본이 어긋남 — 숫자 대신 설치본의 실제 규칙 확인

한계

  • 제안은 출발점. 브랜드 가이드와 접근성 기준이 우선
  • 명시적으로 요청하기 전에는 파일을 고치지 않음 → 진단만 먼저 받기
  • 검색 스크립트 실행에 Python 3 필요

설치 · 업데이트

터미널
python3 --version
npx ui-ux-pro-max-cli init --ai claude

# 업데이트
npm install -g ui-ux-pro-max-cli@latest
uipro update

실전 프롬프트

프롬프트
Use the ui-ux-pro-max skill to design a Korean banking landing page.
먼저 기존 프로젝트의 프레임워크와 버전, 라우트, 컴포넌트, 스타일 파일, 디자인 토큰을 살펴봐.
대상 고객은 모바일을 주로 쓰는 30~50대 개인 고객이야.
기존 컴포넌트 구조, 동작, 로그인 흐름과 비즈니스 로직은 유지해.
신뢰감 있고 읽기 쉬운 색상과 글꼴, 첫 화면 구조를 제안하고 선택 이유와 피할 패턴을 알려 줘.
제안만 먼저 보여 주고, 승인 전에는 파일을 수정하지 마.
03

Diagram Design

구조와 흐름 시각화

svgsingle html

아키텍처, 데이터 흐름, 시퀀스, 일정 비교를 인라인 SVG가 든 HTML 한 장으로 그립니다. 지침은 강조색 하나, 그림자 없음, 4px 그리드입니다.

알아둘 것

  • 4px만 맞춘다고 사람이 그린 것처럼 되지는 않음. 결과는 모델에 따라 달라짐
  • 편집 캔버스 파일이 아님 — 수정은 Claude 요청이나 SVG 직접 편집
  • Git으로 계속 고칠 문서라면 Mermaid가 diff에 유리
  • 기본 HTML은 Google Fonts를 불러옴 → 오프라인은 system font로 요청
  • 서드파티 마켓플레이스 자동 업데이트는 기본 꺼짐

설치

터미널
/plugin marketplace add cathrynlavery/diagram-design
/plugin install diagram-design@diagram-design

다른 호스트: npx skills add cathrynlavery/diagram-design

실전 프롬프트

프롬프트
우리 서비스 구조를 다이어그램으로 만들어 줘.
구성 요소는 React 프론트엔드, Firebase Authentication, Firestore, Cloud Functions야.
사용자가 로그인하고 데이터를 저장한 뒤 다시 조회하는 흐름을 보여 줘.
가장 알맞은 다이어그램 유형을 고르고, 브라우저에서 열 수 있는 HTML 파일 하나로 저장해 줘.
화살표와 라벨이 겹치지 않는지 확인해 줘.
04

Humanizer

AI 문장 패턴 교정

prosediff-safe

패턴은 26개지만 전부를 기계적으로 고치지 않습니다. 강한 5개는 한 번만 보여도 고치고, 약한 패턴은 다른 신호가 함께 있을 때만 적용합니다. 26번째는 대화 답변에 해당하는 “이미 아는 맥락 다시 설명” 문제입니다.

무엇을 걷어내나

  • “단순한 기능이 아니라 새로운 방식” 같은 대비 강조
  • 짧은 극적 결론, 의미 부풀리기
  • 독자가 꺼내지 않은 반론을 먼저 다루는 화법
  • 반복되는 문장 리듬과 부호

한계

  • AI 감지기 통과용이 아님 — 결과도 감지기에 표시될 수 있음
  • 말투를 완벽히 재현하지 않음 → 마지막은 직접 읽고 고침
  • 코드·데이터·frontmatter·링크 대상은 건드리지 않음
  • 제품명·숫자·사실이 그대로인지 diff 확인

설치

터미널
/plugin marketplace add blader/humanizer
/plugin install humanizer@humanizer

Claude Code 2.1.142+ 필요. 이전 버전은 npx skills add blader/humanizer --global --agent claude-code

실전 프롬프트

프롬프트
/humanizer

아래는 내가 직접 쓴 글 샘플이야. 문장 리듬과 말투를 참고해 줘.
[내가 직접 쓴 글 2~3문단]

이제 아래 글을 다듬어 줘.
새로운 사실이나 주장을 추가하지 말고, 원문에 있던 사실과 주장을 보존해.
먼저 고친 패턴과 판단 근거를 간단히 알려 줘.
제품명, 숫자, 링크, 핵심 의미가 바뀌지 않았는지 확인해.
[다듬을 글]
07

안전하게 고치기

진단 → 승인 → 작은 단위

전체를 한 번에 다시 그리게 하면 검토할 수 없는 diff가 나옵니다. 아래 프롬프트는 진단과 계획만 먼저 받고, 승인 뒤 1~2개 컴포넌트씩 고치도록 제한합니다.

프롬프트
현재 프로젝트를 먼저 읽고 사용 중인 프레임워크·버전, 라우트, 공통 컴포넌트, 디자인 토큰을 요약해.
운영 동작과 비즈니스 로직, 접근성 이름, 기존 브랜드 색상은 유지해.
화면에서 AI 템플릿처럼 보이는 구체적 요소를 파일명과 위치별로 진단하고, 개선 우선순위를 제안해.
아직 파일은 수정하지 말고, 각 변경의 목적과 영향 범위를 먼저 보여 줘.
내가 승인하면 한 번에 1~2개 컴포넌트씩 수정하고, 매 단계마다 변경 파일과 남은 작업을 알려 줘.
수정 후 모바일 폭, 키보드 포커스, 색상 대비, 링크와 폼 동작을 확인하고 검증하지 못한 항목은 명시해.

배포 전 확인 — 체크 상태는 이 브라우저에만 저장됩니다.

    이 페이지에 적용한 것

    네 스킬을 이 문서에 돌렸다

    Unslop — 걷어낸 것

    같은 모양의 카드 4장과 3중 박스(표·카드·코드)를 없앴습니다. 코드 위에 겹쳐 있던 복사 버튼은 블록 머리줄로 옮겼습니다. 카드마다 같은 정보를 같은 밀도로 쌓지 않으려고 마커·본문·명령 3단으로 나눴습니다.

    UI UX Pro Max — 정한 것

    액센트는 산화철 주황 하나로 줄이고 링크와 경고에만 씁니다. 제목은 세리프, 숫자와 명령은 모노. 표 대신 행 구분선만 남겼고, 모바일에서도 설치 명령을 숨기지 않습니다.

    Diagram Design — 그린 것

    작업 순서를 번호 목록이 아니라 SVG 타임라인으로 그렸습니다. 선택 단계는 점선과 붉은 원, 아래 브래킷으로 구분했습니다. 좌표는 4px 배수, 그림자 없음, 라벨은 노드 아래 두 줄로 고정했습니다.

    Humanizer — 고친 것

    “단순한 X가 아니라 Y” 류의 대비 문장과 “~할 수 있습니다” 남발, 세 항목 나열을 걷어냈습니다. 확인하지 않은 수치는 쓰지 않았고, 각 스킬의 한계는 그대로 남겼습니다.

    질문

    원문 FAQ 요약

    Anthropic 공식 스킬인가요?

    아니요. 커뮤니티 제작자가 공개한 스킬·플러그인이고 Claude Code의 스킬 기능으로 실행됩니다. 설치 전에 저장소와 권한 요청을 직접 확인하세요.

    다른 AI 도구에서도 쓸 수 있나요?

    일부는 됩니다. Diagram Design과 Humanizer는 저장소가 안내하는 npx skills add 방식으로 다른 Agent Skills 호스트에 설치할 수 있습니다. 호스트마다 지원 범위가 다릅니다.

    Unslop이 운영 사이트를 직접 고치나요?

    아니요. 페이지를 저장해 사본으로 수정 HTML을 만들 뿐입니다. 자동 배포는 없고, 동적 요소는 저장본에서 빠질 수 있습니다.

    Humanizer로 AI 감지기를 피할 수 있나요?

    그 목적으로 만들지 않았고, 제작자도 결과가 감지기에 표시될 수 있다고 밝힙니다. 목적은 탐지 회피가 아니라 읽기 좋은 문장입니다.

    네 개를 모두 설치해야 하나요?

    아니요. 필요한 작업부터 하나씩 쓰면 됩니다. 이미 만든 사이트는 Unslop부터, 구조나 문장만 필요하면 해당 스킬만 설치하세요.

    결과를 그대로 공개해도 되나요?

    결과물의 라이선스와 폰트·이미지 출처를 확인해야 합니다. Diagram Design은 기본 글꼴을 외부에서 불러오므로, 오프라인·자체 호스팅이 필요하면 system font로 바꿔 달라고 요청하세요.
