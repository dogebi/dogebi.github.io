주의 — 네 가지 모두 Anthropic 내장 기능이 아니라 커뮤니티 제작 스킬/플러그인입니다. 설치 전에 저장소 코드와 요청 권한을 확인하고, 결과물의 브랜드 적합성·사실·기능은 사람이 마지막에 검수해야 합니다.

쓰는 순서

전부 설치할 필요는 없다
  1. UI UX Pro Max — 방향 정하기 제품 유형과 고객층을 알려 주고, 색·글꼴·첫 화면 구조와 피할 패턴을 먼저 받는다. 파일 수정은 승인 후에.
  2. Claude Code — 화면 구현 정한 기준을 실제 컴포넌트와 디자인 토큰으로 옮긴다.
  3. Unslop — 렌더링 화면 검토 구현된 화면(또는 라이브 URL 저장본)에서 AI 템플릿 느낌을 위치별로 진단한다.
  4. Diagram Design — 구조 설명 앱 구조·데이터 흐름이 필요하면 다이어그램 HTML을 별도로 만든다.
  5. Humanizer — 문장 점검 공개할 문구와 README의 반복 패턴을 다듬고, 사실·숫자·링크가 그대로인지 확인한다.
  6. 사람 — 최종 검수 후 배포 모바일 폭, 키보드 포커스, 대비, 링크·폼 동작을 직접 확인한다.

이미 만든 사이트를 손본다면 Unslop부터, 다이어그램이나 글 교정만 필요하면 해당 스킬만 써도 됩니다. 순서는 편의일 뿐 전제 조건이 아닙니다.

스킬별 정리

설치 · 프롬프트 · 한계
01

Unslop

이미 만든 화면 점검

무엇을 보나

  • 보라색 그라데이션, 과한 빛 효과, 이모지 라벨
  • 과장된 문구와 근거 없는 최상급 표현
  • 불균형한 간격, 제각각인 아이콘·글꼴
  • 제품 성격과 맞지 않는 레이아웃

제품과 고객층을 먼저 본 뒤 간격 → 색 → 아이콘 → 문구 → 타이포그래피 순서로 개선안을 냅니다. 코드 없이 URL만 있어도 페이지 저장본으로 수정 HTML을 만들 수 있습니다.

한계

  • 운영 사이트를 직접 수정하거나 자동 배포하지 않음
  • 저장본에서 동적 요소가 보존되지 않을 수 있음
  • 결과 HTML은 원본과 비교 후 반영
  • 스토리 영상은 선택 기능 — Playwright·Chromium(+ffmpeg) 필요

설치

claude plugin install unslop --marketplace heydamir/unslop

설치 후 새 세션 또는 /reload-plugins

실전 프롬프트

/unslop https://example.com
이 사이트를 저장해서 원본 화면을 먼저 살펴봐 줘.
제품의 브랜드와 고객층에 맞는 방향을 제안하고, AI 템플릿처럼 보이는 요소를 위치와 함께 진단해.
간격, 색, 아이콘, 문구, 타이포그래피 순서로 개선하고 별도의 HTML/CSS 결과물을 만들어 줘.
운영 사이트에는 배포하지 말고, 변경점과 저장본에서 보존되지 않을 수 있는 요소를 알려 줘.
02

UI UX Pro Max

제품에 맞는 디자인 기준

무엇을 보나

  • 업종·제품 유형에 맞는 화면 구성과 스타일
  • 색상 팔레트와 글꼴 조합
  • 피해야 할 패턴(AI 보라·분홍 그라데이션 등)
  • 기존 프로젝트의 토큰·컴포넌트 구조와의 접점

숫자를 믿지 말 것

  • README: 제품 유형 194 · 팔레트 194 · 글꼴 조합 74
  • 릴리스 노트 v2.15.0: 제품 유형 192
  • 기본 브랜치와 배포 릴리스의 숫자가 다름
  • 필요하면 설치 버전을 고정하고 실제 규칙을 확인

한계

  • 제안은 출발점 — 브랜드 가이드와 접근성 기준이 우선
  • 명시적으로 요청하기 전에는 파일을 바꾸지 않음

설치 · 업데이트

python3 --version
npx ui-ux-pro-max-cli init --ai claude
npm install -g ui-ux-pro-max-cli@latest
uipro update

검색 스크립트 실행에 Python 3 필요

실전 프롬프트

Use the ui-ux-pro-max skill to design a Korean banking landing page.
먼저 기존 프로젝트의 프레임워크와 버전, 라우트, 컴포넌트, 스타일 파일, 디자인 토큰을 살펴봐.
대상 고객은 모바일을 주로 쓰는 30~50대 개인 고객이야.
기존 컴포넌트 구조, 동작, 로그인 흐름과 비즈니스 로직은 유지해.
신뢰감 있고 읽기 쉬운 색상과 글꼴, 첫 화면 구조를 제안하고 선택 이유와 피할 패턴을 알려 줘.
제안만 먼저 보여 주고, 승인 전에는 파일을 수정하지 마.
03

Diagram Design

앱 구조·흐름 시각화

무엇을 만드나

  • 아키텍처, 데이터 흐름, 순서도, 시퀀스
  • 일정표·비교 차트처럼 설명이 필요한 정보
  • 인라인 SVG가 들어간 HTML 파일 하나

디자인 지침은 강조색 제한 · 그림자 없음 · 4px 그리드입니다. AI처럼 보이는 화면을 줄이기 위한 기준이지, 4px만 맞추면 사람 디자인이 되는 것은 아닙니다.

한계

  • 전용 편집 캔버스 파일이 아님 — 수정은 Claude 요청 또는 SVG 직접 편집
  • Git으로 계속 고칠 문서라면 Mermaid가 추적에 유리
  • 서드파티 마켓플레이스 자동 업데이트 기본 꺼짐
  • 기본 HTML은 Google Fonts를 불러옴 → 오프라인은 system font 요청

설치

/plugin marketplace add cathrynlavery/diagram-design
/plugin install diagram-design@diagram-design

다른 호스트: npx skills add cathrynlavery/diagram-design

실전 프롬프트

우리 서비스 구조를 다이어그램으로 만들어 줘.
구성 요소는 React 프론트엔드, Firebase Authentication, Firestore, Cloud Functions야.
사용자가 로그인하고 데이터를 저장한 뒤 다시 조회하는 흐름을 보여 줘.
가장 알맞은 다이어그램 유형을 고르고, 브라우저에서 열 수 있는 HTML 파일 하나로 저장해 줘.
화살표와 라벨이 겹치지 않는지 확인해 줘.
04

Humanizer

AI 문장 패턴 다듬기

무엇을 보나

  • “단순한 기능이 아니라 새로운 방식” 같은 대비 강조
  • 짧은 극적 결론, 의미 부풀리기
  • 독자가 꺼내지 않은 반론을 먼저 다루는 화법
  • 문장 리듬·단어 선택·문장 부호의 반복

패턴은 26개지만 전부를 기계적으로 고치지는 않습니다. 강한 5개는 한 번만 보여도 수정하고, 약한 패턴은 다른 신호가 함께 있을 때 적용합니다. 26번째는 블로그가 아니라 대화 답변에 해당하는 “이미 아는 맥락 재설명” 문제입니다.

한계

  • AI 감지기 통과용이 아님 — 결과도 감지기에 표시될 수 있음
  • 말투를 완벽히 재현하지 않음 → 마지막에 직접 읽고 고쳐야 함
  • 코드·데이터·frontmatter·링크 대상은 건드리지 않음
  • 제품명·숫자·사실·핵심 주장이 바뀌지 않았는지 diff 확인

설치

/plugin marketplace add blader/humanizer
/plugin install humanizer@humanizer

Claude Code 2.1.142+ 필요 · 이전 버전은 npx skills add blader/humanizer --global --agent claude-code

실전 프롬프트

/humanizer

아래는 내가 직접 쓴 글 샘플이야. 문장 리듬과 말투를 참고해 줘.
[내가 직접 쓴 글 2~3문단]

이제 아래 글을 다듬어 줘.
새로운 사실이나 주장을 추가하지 말고, 원문에 있던 사실과 주장을 보존해.
먼저 고친 패턴과 판단 근거를 간단히 알려 줘.
제품명, 숫자, 링크, 핵심 의미가 바뀌지 않았는지 확인해.
[다듬을 글]

안전하게 고치는 법

진단 → 승인 → 작은 단위

한 번에 전체를 다시 그리게 하면 검토할 수 없는 diff가 나옵니다. 아래 프롬프트는 진단과 계획만 먼저 받고, 승인 후 1~2개 컴포넌트씩 수정하도록 제한합니다.

현재 프로젝트를 먼저 읽고 사용 중인 프레임워크·버전, 라우트, 공통 컴포넌트, 디자인 토큰을 요약해.
운영 동작과 비즈니스 로직, 접근성 이름, 기존 브랜드 색상은 유지해.
화면에서 AI 템플릿처럼 보이는 구체적 요소를 파일명과 위치별로 진단하고, 개선 우선순위를 제안해.
아직 파일은 수정하지 말고, 각 변경의 목적과 영향 범위를 먼저 보여 줘.
내가 승인하면 한 번에 1~2개 컴포넌트씩 수정하고, 매 단계마다 변경 파일과 남은 작업을 알려 줘.
수정 후 모바일 폭, 키보드 포커스, 색상 대비, 링크와 폼 동작을 확인하고 검증하지 못한 항목은 명시해.

배포 전 체크리스트 — 체크 상태는 이 브라우저에만 저장됩니다.

    자주 묻는 질문

    원문 FAQ 요약
    이 네 가지는 Anthropic 공식 스킬인가요?

    아니요. 커뮤니티 제작자가 공개한 스킬·플러그인이며 Claude Code의 스킬 기능으로 실행됩니다. 설치 전에 저장소와 권한 요청을 직접 확인하세요.

    Claude Code가 아닌 다른 AI 도구에서도 쓸 수 있나요?

    일부는 가능합니다. Diagram Design과 Humanizer는 저장소가 안내하는 npx skills add 방식으로 다른 Agent Skills 호스트에 설치할 수 있습니다. 호스트별 지원 범위는 다릅니다.

    Unslop은 사이트 주소만 주면 운영 홈페이지를 직접 수정하나요?

    아니요. 페이지를 저장해 사본으로 수정 HTML을 만들 뿐, 운영 사이트를 직접 고치거나 자동 배포하지 않습니다. 동적 요소는 저장본에서 보존되지 않을 수 있습니다.

    Humanizer로 AI 감지기를 피할 수 있나요?

    그 목적으로 설계되지 않았고, 제작자도 결과가 감지기에 표시될 수 있다고 밝힙니다. 목적은 탐지 회피가 아니라 읽기 좋은 문장입니다.

    네 가지를 모두 설치해야 하나요?

    아니요. 필요한 작업부터 하나씩 쓰면 됩니다. 이미 만든 사이트는 Unslop부터, 구조나 문장만 필요하면 해당 스킬만 설치하세요.

    스킬이 만든 결과를 그대로 공개해도 되나요?

    결과물의 라이선스·폰트·이미지 출처를 확인해야 합니다. 특히 다이어그램은 기본 글꼴을 외부에서 불러오므로, 오프라인·자체 호스팅이 필요하면 system font로 바꾸도록 요청하세요.
