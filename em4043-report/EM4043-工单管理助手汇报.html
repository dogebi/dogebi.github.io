Executive brief

先看结论

EM4043 的实测数据已经足以说明，工单助手的核心价值在于统一信息口径，并把信息整理成下一步行动。

工单管理助手不是简单替代人工查询，而是把工单、知识库、历史经验和人员记忆，统一转换为可执行的分析结果。

2. 知识库数据流摘要

  • 接入与任务：Web、第三方 API 或 MCP 通过 FastAPI 接入；上传接口立即返回 task_id，由后台任务异步处理。
  • 解析与切片：根据文件格式进行 Markdown、PDF、Excel、OCR 等解析和清洗，再按 standard、manufacturing、code 等场景策略切片。
  • 基础入库：切片生成 Embedding 后写入原始 Qdrant Collection，同时建立 BM25 关键词索引；文件、切片追踪和状态写入 MySQL，原始与 Markdown 文件保存在文件系统。
  • 元数据增强：LLM 为切片生成 questions、keywords、tags、summary。小规模切片可立即处理，中等规模进入 Redis 队列由独立 Worker 异步处理，大规模任务进入待处理状态。
  • 智能检索：smart_search 根据增强开关选择标准 HybridRetriever 或 MultiVectorRetriever；原始内容与增强元数据分别进行向量检索和 BM25 检索，再按 slice_id 融合。
  • 排序与输出：融合结果经过阈值过滤、Reranker 和可选的 LLM Refine，返回最终 Top-K；PDF 还可通过独立的 PageIndex 树进行章节级推理检索。
  • 存储与协同：Qdrant 保存原始/增强向量，MySQL 保存业务元数据和增强记录，Redis 管理任务队列与缓存，文件系统保存 Markdown、BM25 索引和 PageIndex 树。

核心价值：非结构化资料经过“解析—切片—向量化—关键词索引—元数据增强”形成可持续迭代的知识资产；Agent 可根据问题类型选择语义、关键词、增强元数据或章节结构进行检索。

Business scenarios

覆盖从故障受理到服务交付的业务场景

工单助手不仅服务于单一的故障处理，也覆盖咨询协助、资产操作、变更管理和 CSC 请求等日常服务流程。通过统一的业务分类，可以让不同类型的工单使用一致的查询、分析和报告方法。

当前故障申报类型的实测情况

在 EM4043 项目中，故障申报类工单共有 2 张，占全部 15 张工单的 13.3%。其中，EM4043-10 为监控告警类故障，处理时长为 1 小时 26 分钟；EM4043-14 为同类 swap space usage 告警，当前已恢复。该类型适合重点展示故障影响识别、处理进展跟踪和客户反馈生成能力。

Four user scenarios

四类用户，四种结果

同一批工单数据，按照不同角色的工作目标重新组织，直接服务于客户沟通、技术处理和管理决策。

T1

客户问题快速定位与反馈

关注是否及时受理、当前进展、预计方向和最终客户反馈。

客户沟通

传统人工方式

  • 在 Jira、历史文档、聊天记录和经验库之间反复查找。
  • 人工确认状态、负责人和处理进展。
  • 手工整理问题描述、处理过程和客户回复。
  • 交接班容易遗漏待办事项和风险信息。

工单助手输出

  • 问题概述与当前影响范围。
  • 已完成动作、负责人和工单状态。
  • 下一步处理建议和客户可读说明。
  • 交接待办与风险提示。
  • 导入 KB（知识库）内容，辅助问题定位。

T1 典型工作场景

  1. 上班后先查看当前待处理和未关闭工单，快速掌握当天需要优先跟进的事项。
  2. 手上约 20 个工单时，系统按状态、优先级、负责人和交接信息整理每张工单，直接展示当前情况和下一步，减少人工过滤和逐单确认时间。
  3. 对新发生故障，自动生成初次故障报告，包含故障现象、影响范围、发现时间、当前状态和初步处理建议，便于内部升级和客户首次反馈。
核心收益 T1 可以从“逐单查找和确认”转为“按优先级处理和跟进”，缩短上班后的工单整理时间，并加快首次故障报告生成。

EM4043 实测依据

项目共 15 张工单，已关闭或完成 9 张，占 60%；处理中或未完结 6 张，占 40%。故障申报类工单 2 张，EM4043-10 的监控告警处理时长为 1 小时 26 分钟，EM4043-14 为同类告警且已恢复。

演示问题请查询 EM4043 项目当前未关闭的故障工单，说明影响、当前状态、负责人和下一步处理建议，并生成一份客户可读的处理进展说明。Demo
T2

技术问题分析与解决方案生成

关注根因分析、影响范围、历史相似问题和可执行的处理方案。

技术处理

传统人工方式

  • 手动检索历史工单、知识库和变更记录。
  • 依靠个人经验判断可能根因。
  • 人工比对相关设备、资产和近期变更。
  • 排查、回滚和验证方案需要单独编写。

工单助手输出

  • 区分故障现象、已确认事实与推测内容。
  • 关联历史案例、近期变更和影响范围。
  • 生成排查步骤、处理方案和回滚方案。
  • 列出变更后的验证项目。
  • 通过 SOP 蒸馏，沉淀可复用的处理流程。

EM4043 实测依据

变更相关工单共有 10 张，占总工单数 66.7%。EM4043-2、3、8、9 分别涉及互联网访问阻止策略、工程师处理变更、黑名单阻止策略和关联工程师处理变更，适合联合分析处理进度与技术风险。

演示问题请分析 EM4043-2、EM4043-3、EM4043-8 和 EM4043-9 的关联关系，区分已确认事实与推测，并输出排查步骤、处理建议和回滚方案。
Admin

工单统计、人员负载和异常管理

关注全局运行情况、状态分布、负责人、处理时长和异常事项。

全局管理

传统人工方式

  • 找不同负责人询问状态，再手动汇总。
  • 导出 Jira 数据后制作统计表。
  • 人工识别超时工单和长期未关闭工单。
  • 统计结果生成慢，容易出现遗漏或口径不一致。

工单助手输出

  • 直接回答总数、类型、未关闭工单和负责人。
  • 筛选处理时间超过 3 小时的工单。
  • 识别长期停滞事项和管理介入点。
  • 形成每日、每周和月度管理看板的基础。

EM4043 实测依据

处理时间超过 3 小时的工单有 6 张，超过 21 小时仍未解决的工单有 3 张，未完结工单累计占用时长约 93 小时。EM4043-2、3、8 是当前需要重点关注的事项。

演示问题请生成 EM4043 项目当前工单管理报告，包含总数、状态、类型、负责人、超过 3 小时的工单、长期未解决事项和管理建议。
SM

客户月报、项目统计和管理分析

关注客户月报、项目趋势、服务质量、工单分类和资源投入情况。

客户汇报

传统人工方式

  • 从 Jira 导出数据，再找 T1、T2 和负责人补充情况。
  • 手工整理月度统计和处理时长。
  • 制作 Word、Excel 和 PPT，反复确认口径。
  • 报告制作占用大量时间，数据容易不一致。

工单助手输出

  • 按项目和统计周期生成工单总量及类型分布。
  • 输出完成率、平均处理时长和超时工单。
  • 提炼重点风险、主要处理人员和管理结论。
  • 同时生成管理版与客户可读的月报初稿。
  • 可调用 Skill 生成月报、季报等标准化报告。

EM4043 实测依据

已关闭或完成工单平均处理时长约 6 小时 37 分钟，未完结工单累计占用时长约 93 小时，目前存在 3 张超过 21 小时仍未解决的工单。这些数据可以直接转化为月报中的服务质量与风险结论。

演示问题请生成 EM4043 项目月度服务报告，包含工单数量、类型分布、完成率、处理时长、长期未解决事项、主要风险和下月改进建议。

Key challenges

面临的主要课题

下一阶段重点在于提高知识基础的完整性、控制复杂查询的执行成本，并提升系统稳定性。

  • 知识库工单、资产知识库的完整性与持续优化，以及查询机制的进一步完善。
  • 复杂查询Agent 调用 MCP 时偶尔生成过于复杂的查询，导致执行时间过长甚至卡死。
  • 系统稳定性持续排查系统资源或业务逻辑问题导致的故障，完善监控、定位和恢复机制。
