modを安全に使う方法

modはサンドボックスなしで、自分の権限のままClaude Codeの中で動作します。そのため、インストールする前に何ができるのかを把握しておくことが重要です。この記事では、modが届く範囲、インストール前に自分で確認する方法、k-modsがレビューする基準と権限ラベル、組織の管理者が使える統制、注意すべき兆候を整理します。

modにサンドボックスはありません

modが一度読み込まれると、こんなことができるようになります。

  • 自分のコンピューター上で自分と同じように振る舞う: 自分のアカウントが届くあらゆる場所でファイルを読み書きし、プログラムを実行し、ネットワークリクエストを送ります。
  • 自分の秘密情報の読み取り: 環境変数と設定ファイルを読みます。そこに入っているAPIキーも含まれます。
  • 自分のセッションを閲覧: 自分が送るすべてのプロンプトと、Claudeが呼ぶすべてのツールを見ます。
  • 自分のセッションを変更: プロンプトやツール呼び出しを書き換えたり、自分が打ったかのようにプロンプトを代わりに送ったり、自分の別のセッションにメッセージを送ったりできます。
  • 尋ねずに行動: ユーザーに尋ねる前にツール呼び出しを承認できます。
  • 自分の使用量を消費: 自分のプランやAPIキーでモデルを呼び出します。

サンドボックスを有効にしていてもmodは影響を受けません。サンドボックスはClaudeが実行するBashコマンドだけを隔離し、modが直接起動したプロセスはサンドボックスの外で動作します。

ツール呼び出しを承認するmodは ask ルールが問い合わせる呼び出しや、自分の PreToolUse フックが止めた呼び出しも代わりに承認できます。さらに managed settingsがなく、Team・Enterpriseプランでログインしていない個人ユーザーなら、内蔵ガード(sec-default@builtin ）がまったく読み込まれないので deny ルールでブロックした呼び出しまで、modが覆して承認できてしまいます。ただしmodはClaude Codeの 権限確認のダイアログ自体は変更できません。 ユーザーに何を表示するかは操作できません。(公式ドキュメント: Extend permissions with hooks)

インストール前に自分で確認する

マーケットプレイスからすぐにインストールする前に、そのmodが受け取るイベントと呼び出すAPIを、実行せずに確認できます。リポジトリをクローンしたうえで、シェルで実行してください。

claude plugin validate ./some-mod
  ❯ ./register.js hooks: session.start, tool.call, ui.render{component=Pane}
  ❯ ./register.js calls: $.fs.read, $.http.fetch, $.store.set, $.ui.open

calls: 行で特に注目したい項目です。

呼び出し 意味
$.fs.read, $.fs.write 自分のアカウントが届く場所ならどこでもファイルを読み書きします
$.process.run, $.process.spawn 自分の権限でプログラムを実行します
$.http.fetch ネットワークリクエストを送信します
$.env.get, $.settings.read 環境変数・設定を読みます。APIキーが含まれている可能性があります。出力の env reads: 行にどの変数かが表示されます。
$.env.set 環境変数を設定します。以降Claude Codeが実行するすべてのコマンド・MCPサーバーに影響する可能性があります。 env writes: 行にどの変数かが表示されます。
$.mcp.call 接続されたMCPサーバーのツールを、セッションの権限ルールのもとで呼び出します
$.model.complete 自分のプランやAPIキーでモデルを呼び出します
$.prompt.submit プロンプトを代わりに送信します。自分が入力したように見せかけることもできます
$.session.send 他のセッションやサブエージェントのClaudeが読むメッセージを送信します

hooks: 行では次の点が重要です。 tool.call と prompt.submit は、すべてのツール呼び出しとプロンプトを見て変更できるという意味で、 session.append は、会話の各行を保存される前に書き換えられるという意味です。 ui.render{component=AskUserQuestion} は、Claudeがユーザーに尋ねるダイアログを描き直せるという意味で、 tool.checkは、権限確認画面が表示される前にツール呼び出しを承認・拒否できるという意味です。

公式ドキュメント: Review what a mod can do

k-modsのレビュー方法

k-modsカタログに掲載されたmodは、インストール前にこうした過程を経ます。

  1. ライセンスゲート: ライセンスのないリポジトリのコードは、作者の許可を得るまでは公開しません。
  2. コミット固定(sha): 原本をそのまま取り込むmodは、レビューした時点の正確なコミットを固定します。原本リポジトリが後で変わっても、自分が受け取るのはレビューしたそのコードのままです。アップデートは再レビューの後にだけ公開します。
  3. 静的解析 + コード読み込み: claude plugin validateを通過するか確認し、人がコード全体を読みます(code-read）。modにテストがあれば通るかも確認し（unit-test）、画面を描くmodは実際のセッションで一度表示して確認します（live-session）。各modページの「レビュー方法」に、どんな過程を経たかが書かれています。
  4. 権限ラベルの表示 : 静的解析で見つけた呼び出しをもとに、このmodが自分のコンピューターで行うことをラベルとして付けます。下の 権限ラベル 参考。
  5. アップデート時に再レビュー: バージョンが上がったmodは、最初に公開したときと同じ過程をもう一度通ります。
  6. 作者の要請により削除: 原作者が削除を求めたら、すぐにカタログから外します。

公式ドキュメント: Plugin security and trust

権限ラベル

各modページには、静的解析で見つかった権限がラベルとして付いています。危険なものから順に並べています。

ラベル 意味
🌐 ネットワーク $.http や $.mcpでインターネットや外部サーバーと通信します。会話内容が外部に出る可能性があるため、送信先を確認してください
⚙️ プログラム実行 $.processで自分のコンピューター上でプログラムを実行します
✏️ ファイル書き込み $.fs.writeでファイルを書き込みます
🤖 モデル呼び出し $.modelでモデルを呼び出します。自分の使用量を消費します
🛡️ ツール呼び出しの制御 tool.call や tool.check フックでツール呼び出しを止めたり、代わりに答えたりできます
💬 プロンプト入力 $.prompt.submit や $.prompt.fillでプロンプトを代わりに入力したり送信したりします
👀 会話読み取り prompt.submit·turn.complete·session.append フックや会話を描画する画面、 $.session.messagesで会話内容にアクセスします
🔑 環境・設定の読み取り $.env や $.settingsを読みます
📂 ファイル読み取り $.fs.read 系のファイルを読みます
📨 セッションメッセージ $.session.sendで他のセッションにメッセージを送信します
🔊 音 $.audioで音を鳴らします
🎨 画面のみ 上記のどれも行わず、画面を描画するだけです

ラベルの読み方。 画面を描画するmodは、ほぼすべて👀(会話読み取り)が付きます。ターンが終わったというシグナルだけを受け取っても、Claudeの最後の回答が一緒に入ってくるからです。そのため、👀だけを心配する必要はありません。本当に見るべきは 組み合わせです。👀があっても、🌐(ネットワーク)・⚙️(プログラム実行)・💬(プロンプト入力)がなければ、そのmodが会話を端末の外に持ち出す方法はありません。💬はClaudeに代わりに送ってもらう抜け道になり得るため、あわせて確認します。逆に👀と🌐が揃っている場合は、modページの「コード内のアドレス」とレビューノートで、どこに何を送っているかを必ず確認してください。

1つのmodにラベルが複数付くことがあります。ラベルがなければ、画面だけを変えるmodという意味です。

k-modsのmodページの読み方

各modページ(または /pluginで確認できる詳細情報)で、次の点を確認してください。

  • 種類(kind): 오리지널 （k-modsが最初から作成）、 한국 수정판 （原本をk-modsが修正）、 원본 （原本そのまま、コミットだけ固定）、 묶음（他のmodを複数まとめたインストールセット）
  • 権限ラベル: 上の表のラベル
  • レビュー記録: レビュー日、レビューに使ったClaude Codeのバージョン、レビュー方法（validate/code-read/unit-test/live-session）、レビュー中に見つかった点（ネットワークの宛先、外部プログラムの実行など）
  • 出典: 原本modなら原作者のリポジトリと固定したコミットのリンク。修正版なら原本と何を変えたか

疑問な点があれば、インストール前に claude plugin validate <복제한 폴더>で、もう一度自分で確認してみてください。

会社・組織で使う場合

会社のClaude Code環境であれば、管理者がmodポリシーを別途設定できます。

  • allowManagedModsOnly: 有効になっていると、ユーザーがインストールしたmodはまったく読み込まれず、組織が配布したmodとClaude Codeの組み込みmodだけが動きます。k-modsのmodもこのポリシーの下では読み込まれないことがあります。
  • prependPlugins/appendPlugins: 組織のポリシーmodをユーザーmodより先に（または後に）実行するよう順序を決めます。
  • sec-default@builtin : managed settingsがあるか、Team・Enterpriseプランでログインしている場合に、ユーザーがインストールしたすべてのmodより先に読み込まれる組み込みガードです。組織が管理するシステムプロンプト、managed CLAUDE.md、managed MCPサーバーのツール・説明はユーザーmodが触れないように守ります。それ以外は特にブロックしません。

会社の環境で特定のk-mods modが表示されない場合は、まずこれらのポリシーが原因かどうかを確認してください。管理者側の設定方法は公式ドキュメントにあります。

公式ドキュメント: Manage mods for your organization

こんなmodには注意してください

  • calls: 行に $.http.fetch や $.process.runがありますが、説明のどこにもなぜ必要なのかが書かれていません。
  • hooks: 行に prompt.submit や session.appendがありますが、会話内容を端末の外に送信しないという説明がありません。
  • tool.checkのようにツール呼び出しを承認・拒否できるmodですが、ソースが非公開だったり、どのコミットを受け取るのか分からなかったりします。
  • ライセンスがまったくないリポジトリのコードです。
  • トークンやパスワードを受け取りながら userConfig の sensitive 表示なしで平文のまま保存します。
  • 「画面だけを変える」という説明なのに、🌐 ネットワークや ⚙️ プログラム実行のラベルが付いています。説明と権限が食い違う場合は、コードをもう少し読んでみるのがおすすめです。
