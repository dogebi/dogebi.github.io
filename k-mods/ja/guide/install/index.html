インストールガイド

k-modsは通常のClaude Codeプラグインマーケットプレイスです。そのためインストール・アップデート・削除はすべてClaude Codeの /plugin コマンドと claude plugin シェルコマンドで行えます。この記事では、バージョン確認からマーケットプレイスの追加、インストールスコープ（scope）、チームメンバーと一緒に使う方法、トラブルシューティングまでを順番にまとめます。

バージョン確認

modを読み込むには最低バージョンが必要です。

  • ターミナル : Claude Code 2.1.287以上。シェルで claude --versionで確認します。
  • デスクトップアプリ : 2.1.286以上。Codeタブで /status を入力すると Claude Code の行にバージョンが出ます。

バージョンが低い場合は、Claude Codeかデスクトップアプリをアップデートしてから再試行してください。

公式ドキュメント: Turn mods on or off

マーケットプレイスを追加

k-modsをインストールするには、まずマーケットプレイスを一度登録する必要があります。セッション内で行っても、シェルで行ってもかまいません。

セッション内で

/plugin marketplace add dogebi/k-mods

シェルで （セッションを開かず、スクリプトなどから） 

claude plugin marketplace add dogebi/k-mods

成功したら Successfully added marketplace: k-mods が表示されます。マーケットプレイス名はリポジトリ名ではなく marketplace.json の name フィールドから来ますが、k-modsでは両者が同じです。以降は <mod 이름>@k-mods という形でインストールします。

公式ドキュメント: Add a marketplace

インストールする

セッション内で

/plugin install starter@k-mods

セッションで /plugin install はすぐにはインストールせず、まず /plugin パネルでそのmodの詳細情報（説明、追加されるコマンド・フック、権限）を表示します。そこでインストールスコープを選ぶと、そのときにインストールされます。

シェルで （すぐにインストール） 

claude plugin install starter@k-mods

k-modsがあらかじめまとめたセットもあります。

  • starter@k-mods: おすすめセット。READMEの「まず使ってみてください」にあるmod（ko-ui, skins, pixel-pals, ctx-strip, mod-store）が一度にインストールされます。
  • korean-pack@k-mods: 韓国語パックのみ（メニュー・設定・タスクバーの翻訳、ko-ui）。

1つずつ選んでインストールしたいなら mod-store@k-mods をインストールした後、セッションで /k-modsを入力してください。カタログがパネルで開き、ボタンでインストール・削除できます。

公式ドキュメント: Install a plugin

インストールスコープ（scope）

インストール時に3つのスコープから1つを選びます。スコープは「誰がこのmodを受け取るか」と「どの設定ファイルに記録されるか」を決めます。

スコープ 誰が受け取るか 記録されるファイル
user（ユーザー） このコンピューターのすべてのプロジェクトで自分だけ ~/.claude/settings.json
project（プロジェクト） このリポジトリで作業する全員 .claude/settings.json （コミットするファイル）
local（ローカル） このリポジトリで自分だけ .claude/settings.local.json （通常はコミットしない）

シェルでは --scope user|project|local で選び、省略すると userです。

claude plugin install blast-radius-ko@k-mods --scope project

同じmodが複数のスコープに同時に設定されていると local > project > user の順に優先されます。たとえばプロジェクトが有効にしているmodを自分だけオフにしたいなら、localスコープでオフにすればかまいません。

公式ドキュメント: Choose an install scope

無効化・削除する

セッション内で: /plugin → Installed タブで項目を選ぶと Disable plugin, Uninstall 同じメニューが出ます。 /plugin enable <mod>@k-mods, /plugin disable <mod>@k-mods, /plugin uninstall <mod>@k-modsで直接開くこともできます。

シェルで

claude plugin disable blast-radius-ko@k-mods
claude plugin enable blast-radius-ko@k-mods
claude plugin uninstall blast-radius-ko@k-mods --scope project

enable·disable は --scope を省略すると、そのmodがすでに設定されているスコープを自動で探します。 uninstall は省略すると user スコープを削除します。

プロジェクトが有効にしているmodを Uninstall すると「自分だけオフにするか、全体から外すか」を尋ねます。自分だけオフにするには .claude/settings.local.json に false を書く側（デフォルトキー y）を、全体から外すには共有ファイル自体を変える側（u）を選べばOKです。

公式ドキュメント: Manage installed plugins

セッションにすぐ反映する

シェルでインストール・アップデート・削除したか、 /plugin パネルの外で設定ファイルを変えた場合、開いているセッションには自動では反映されません。セッション内で次のように入力してください。 

/reload-plugins

/plugin パネルを閉じるときに変更があれば、Claude Codeが自動で /reload-plugins を実行してくれます。ただし、今回のリロードがプロンプトキャッシュを壊す可能性がある場合（MCPサーバーが追加・削除される場合など）は、すぐには適用せず警告だけ出します。そのときは /reload-plugins --forceで強制適用できますが、次のリクエスト1回はキャッシュなしで処理されるためコストが余計にかかります。

公式ドキュメント: /reload-plugins

インストール済みmodを確認する

セッション内で /plugin を入力すると、タブの下に薄い文字で N mods active · 이름1, 이름2 のように表示されます。この行には 組み込みmodは含まれません。 インストールしたのにこの行に名前が見えないなら、読み込みに失敗しています。

シェルではより詳しく見られます。

claude plugin list
claude plugin details mod-store

plugin list はバージョン・スコープ・状態を表示し、 plugin detailsは、そのmodが追加するコマンド・フック・エージェントの一覧とコンテキストコストを表示します。

公式ドキュメント: See which mods a session loaded

設定値を入れる（userConfig）

一部のmodはインストール時に追加の値を尋ねます（APIアドレス、トークンなど）。これらの値はプラグインの userConfigとして宣言されています。

  • インストール・有効化のタイミング: 値が空なら設定ダイアログが自動で開きます。
  • 後で開き直す : セッションで /plugin configure <mod>@k-modsを入力します。
  • 一目でわかる概要 : Claude Code 2.1.269以上なら /config パネルには有効なmodごとに設定行が表示されます。ただし、機密性の高い値（ sensitive）や複数を選ぶ値（multiple ）は /configに表示されません。
  • シェルで値を入れる : インストールするときに --config key=valueを付けたり、インストール後に次のようにJSONを標準入力へ流し込みます。
echo '{"api_url": "https://example.com"}' | claude plugin configure my-mod@k-mods --values-stdin

機密性の高い値は settings.jsonではなく、OSの安全なストア（macOSキーチェーンなど）に保存されます。

公式ドキュメント: User configuration

最新バージョンを保つ

マーケットプレイスごとに自動アップデートのデフォルトが異なります。

  • デフォルトでオン: Anthropic公式マーケットプレイスのほとんど
  • デフォルトでオフ: k-modsを含むその他すべてのマーケットプレイス

k-modsは自動アップデートがデフォルトでオフなので、最新のレビュー・バグ修正を受け取るにはときどき次のいずれかを行ってください。

  • セッションで自動アップデートを有効にする: /plugin → Marketplaces タブ → k-mods 選択 → Enable auto-update

  • マーケットプレイスのカタログだけを更新 （新しいmodを追加するか確認、インストール済みのmodはそのまま） 

    claude plugin marketplace update k-mods

  • インストールしたmodまでまとめてアップデート : セッションで /plugin → Marketplaces タブ → k-mods 選択 → Update marketplace

  • modを1つだけアップデート

    claude plugin update starter@k-mods

公式ドキュメント: Keep plugins updated

チームメンバーと一緒に使う

リポジトリに設定をコミットしておくと、そのリポジトリを開くすべてのチームメンバーにk-modsマーケットプレイスが自動で登録され、指定したmodが「オン」状態で始まります。 .claude/settings.jsonに次のように書いてコミットしてください。

{
  "extraKnownMarketplaces": {
    "k-mods": {
      "source": { "source": "github", "repo": "dogebi/k-mods" }
    }
  },
  "enabledPlugins": {
    "starter@k-mods": true
  }
}

シェルで一度実行するだけで、このファイルが自動で作られます。

claude plugin marketplace add dogebi/k-mods --scope project
claude plugin install starter@k-mods --scope project

注意点: enabledPluginsに書かれたmodは「オン」状態になるだけで、チームメンバーのコンピューターへ自動でダウンロードされるわけではありません。リポジトリを新たに取得した各メンバーは、一度ずつ次のコマンドを実行しないと実際にはインストールされません（ワークスペースを信頼（trust）した後）。

claude plugin install starter@k-mods --scope project

この手順を省くと、Claude Codeが「.claude/settings.jsonこのプラグインを有効にしているがインストールされていない」と知らせます。

トラブルシューティングのチェックリスト

modはインストールできたのに何も起きない場合は、上から下へ確認してみてください。

  1. バージョンが低すぎる: claude --version またはデスクトップアプリの /status 確認。 バージョン確認 参考。

  2. ワークスペースをまだ信頼（trust）していない: このディレクトリでインタラクティブセッションを一度開き、信頼確認のダイアログを承認しないとmodは読み込まれません。

  3. --bare や --safe-modeで始まる: この2つのフラグはインストール済みのmodをすべて無効にします。フラグなしで再起動してみてください。

  4. disableAllHooksが設定済み : 自分の設定ファイルや組織のmanaged settingsにこの値が trueならインストールしたmodがすべて無効になります。

  5. 組織ポリシーでブロックされている : 管理者が allowManagedModsOnly を有効にしたなら、組織が配布したmodだけが読み込まれます。詳しくは 安全ガイドにあります。

  6. /pluginの「N mods active」の行に名前がない : インストールはできたものの、読み込みに失敗したということです。 claude plugin validate <경로>で先に確認するか、下のデバッグログを見てください。

  7. デバッグログを確認: シェルで次のように実行すると、なぜ表示されないかの理由がログに1行残ります。

    claude --debug-file ./mod-debug.log --plugin-dir ./문제의-mod
tail -f ./mod-debug.log | grep 문제의-mod
