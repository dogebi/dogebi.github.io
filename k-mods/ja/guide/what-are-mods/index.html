modsとは？

modはClaude Code 2.1.287から使える公式機能です。プラグイン(plugin)の中のJavaScript・TypeScriptコードが、ツール呼び出しやプロンプト送信といったイベントを直接受け取って、Claude Codeの動作を変えたり画面を描画したりします。この記事では、modとは正確に何なのか、何ができるのか、どこで動作するのか、似た他の機能と何が違うのか、どうやってオン・オフするのかを整理します。

一行定義

mod は Claude Codeの中で直接実行されるプラグイン(plugin)のコードです。ツール呼び出し、プロンプト送信、画面描画のように、Claude Codeが何かをしようとする瞬間ごとに「イベント(event )」が発生しますが、modはJavaScriptやTypeScriptで書いた関数(フック、 hook)でそのイベントを受け取り、監視したり、変更したり、いっそ横取りして代わりに処理したりします。

一行の自己要約: modはClaude Codeのイベントの間に割り込むミドルウェア(middleware)です。見て、変えて、代わりに答えます。

Claude Codeは設定ファイルで登録する従来の方式も「フック」と呼びますが、k-modsのドキュメントで「フック」は常にmodのハンドラーを指します。シェルコマンド・HTTPリクエスト・プロンプトで動作する従来の方式は「設定フック(settings hook)」と呼んで区別します。

公式ドキュメント: Mods overview

どのように動作するのか

1つのmodのコード(フックモジュール、 hooks module )は register(on) 関数をエクスポートし、その中で on(이벤트 이름, 핸들러)でイベントを登録します。Claude Codeはハンドラーに3つを渡します。

  • $: mod APIです。画面を描画したりファイルを読んだりするなど、外の世界と接する唯一の窓口です。
  • e: イベントデータです。読み取り専用なので書き換えはできません。
  • next: 次のハンドラー(別のmod、またはClaude Code自体の動作)を呼ぶ関数です。

ハンドラーはこの3つのいずれかでイベントを処理します。

処理方式 やること コード
観察(observe) そのまま流します return next(e)
変形(rewrite) 内容を変えて流します return next({ ...e, text: e.text.trim() })
応答(answer) nextを呼ばずに直接答えてチェーンを切ります return { deny: '이유' }

たとえば、ツール呼び出しのたびにカウントを増やしてスピナーの横に表示するmodは、こんな形になっています。

let calls = 0

export function register(on) {
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render') // 화면을 다시 그려 달라고 요청
    return next(e) // 도구는 평소대로 실행
  })

  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ' · 도구 ' + calls + '번' } })
  })
}

1番目のフックは tool.call を観察するだけで、2番目のフックは ui.render を変形して、スピナーの文言の後ろに呼び出し回数を付けます。同じイベントに複数のmodが登録されている場合は、ミドルウェアチェーンのように順番に実行されます。登録順序のルールと失敗時の処理は チートシート と 自分だけのmodを作るでさらに扱います。

公式ドキュメント: How a mod works, React to events

modにできること

設定フック、スキル、ステータスライン(status line )、MCPサーバーはすべてClaude Code 外部 で動きます。スクリプトを実行したり、Claudeに文章やツールを渡したりするだけです。modはClaude Code ないで動作するため、こんなことができます。

  1. 画面描画: トランスクリプト横のパネル(pane)や入力欄の上の帯(AbovePrompt)にタブ、ボタン、入力欄を描画します。
  2. Claude Code自体の画面の再描画: ツール呼び出しの行、スピナー、Claudeが質問するときのダイアログなどを変更したり、新しく描画したりします。
  3. ツール呼び出し・リクエストの横取り: ツール呼び出しを一時停止してユーザーに尋ねたり、実行せずにすぐ答えたり、リクエストを1つだけ別のモデルに送ったりします。
  4. コマンドで自分のコードをすぐ実行 : Claudeのターンなしで即時実行される /명령어を追加します。Claudeが作業中でも実行されるようにできます。
  5. フック同士のデータ共有: 1つのmod内のフックは同じファイルの変数を共有します。あるフックがツール呼び出しの回数を数え、別のフックがその値を画面に表示する、といった具合です。

公式ドキュメント: What a mod can do

どこで動作するのか

modのフックは、プラグインが読み込まれるすべてのセッションで実行されます。ただし 画面を描画する機能はターミナルとデスクトップアプリでのみ表示されます。

実行環境 フック実行 画面表示
ターミナル(claude)、エディタ統合ターミナル、JetBrainsプラグイン 済み 表示
デスクトップアプリのCodeタブ(WSLセッションを除く) 済み 表示(ターミナル専用要素の一部を除く)
デスクトップアプリのWSLセッション 不可(WSLではプラグイン自体が使えない) 非表示
VS Code拡張のチャットパネル 済み 非表示
claude -p, Agent SDK 済み 非表示
claude.ai・モバイルアプリのリモートコントロール(Remote Control) 可能(自分のコンピューターのセッションで) 自分のコンピューターのターミナルにのみ表示
クラウドセッション プラグインがクラウドセッションまで届く場合のみ可能 非表示

画面を描画するmodは、いまどのアプリで動いているかを確認して、描画できない場所ではトランスクリプトの行やコマンド応答のテキストで代替するのがおすすめです。

設定フック・スキル・MCPとの違い

mod 設定フック(settings hook) スキル(skill) MCPサーバー
正体 Claude Codeプロセスの中で直接動作するプラグイン関数 ライフサイクルイベントでClaude Codeが実行するシェルコマンド・HTTPリクエスト・プロンプト Claudeが読む指示が入った SKILL.md 外部プロセス・サービスがClaudeにツールを渡す
変えられるもの ツール呼び出し、プロンプト、コマンド、ターン、画面に描画する内容 イベントの進行可否、ツール呼び出しの引数・結果、Claudeに追加されるコンテキスト Claudeが知っていることと行うこと Claudeが使えるツール
画面を描画するか 可 不可 不可 不可
何で作るのか JavaScript・TypeScript スクリプト + settings.json 項目 Markdown 任意の言語で作ったサーバー
いつ選ぶのか パネルや入力欄の上の帯が必要なとき、カスタムコマンドが必要なとき、イベント自体を変える必要があるとき 既存のスクリプトでイベントをブロックしたり許可したり記録するだけで足りるとき 同じ指示を何度も貼り付けているとき Claudeが外部システムに接続する必要があるとき

1つのプラグインがmod、スキル、MCPサーバーを同時に含むこともあります。k-modsの mod-storeのようにコマンド(/k-mods)と画面描画を併せ持つmodがその例です。

Claude Codeに内蔵されたmods

Claude Code自体の機能の一部もmodで作られています。 /plugin → Installed タブの Built-in 以下で確認でき、アップデート・削除はできませんが、オフにすることはできます。

/pluginに表示される名前 やること オフにする方法
cc-plugin-agents-md AGENTS.mdをプロジェクト指示として読み込む /pluginでオフにするか、どの指示ファイルを使うかの設定を変更
cc-plugin-diff /diff コマンドとそのパネルを担当 /plugin でオフにすると /diffはClaude Codeの基本バージョンで動作
cc-plugin-plugin-authoring modを使うための plugin-authoring スキルを提供 /pluginでオフにする
cc-plugin-sec-default ユーザーがインストールしたmodから、組織が管理する設定を守る ユーザーはオフにできない。管理者がmanaged settingsで順序を決める
cc-plugin-telemetry Claude Codeと内蔵modsの使用量記録の送信 /pluginでオフにするか、分析機能自体を無効化(DISABLE_TELEMETRY など)
cc-plugin-you-should-know 作業が長引くときに見落としやすい点を教えてくれる補助エージェント デフォルトはオフ。 /pluginでオン・オフ

diff, agents-md, sec-default, telemetry のソースは claude-codeリポジトリのmodsディレクトリにテストまで含めて公開されています。実際のmodコードがどうなっているかを参考にするのに向いています。

公式ドキュメント: Mods built into Claude Code

modsのオン・オフ

無効にする範囲によって方法が異なります。

  • modを1つだけ: /plugin → Installed タブで無効化するか削除します。
  • 今回のセッションのすべてのmod: claude --safe-modeで始まります。他のカスタマイズも同時にオフになります。
  • 自分がインストールしたすべてのmod、すべてのセッション: ~/.claude/settings.json に "disableAllHooks": trueを設定します。設定フックとカスタムステータスラインも一緒にオフになり、組織が管理しているものだけが動作し続けます。

組織に所属している場合は、管理者がmanaged settingsでmodの読み込み自体をさらに制限することもあります。詳しくは 安全ガイドにあります。

アーリーアクセスのとき CLAUDE_CODE_ENABLE_FUNCTION_HOOKS を設定している場合は削除してください。Claude Code 2.1.287からはこの変数を無視するため 0にしてもmodはオフになりません。

公式ドキュメント: Turn mods on or off

バージョン要件

  • ターミナル : Claude Code 2.1.287 以上。 claude --versionで確認します。
  • デスクトップアプリ : 2.1.286以上。Codeタブで /status を入力すると Claude Code の行にバージョンが出ます。

バージョンが低いと、modはインストールできても読み込まれません。インストール・アップデートの方法は インストールガイドをご覧ください。
