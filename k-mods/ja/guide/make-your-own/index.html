自分だけのmodを作る

modを作る方法は2つです。Claudeに言葉で指示するか、自分でコードを書いてもかまいません。この記事では両方の方法を扱い、最後に完成したmodをk-modsに公開する手順へ続きます。

Claudeにやらせる

最も速い方法です。セッション内で望むことをそのまま伝えればOKです。

입력창 위에 현재 git 브랜치를 보여주는 mod 만들어 줘

Claudeは組み込みスキルの plugin-authoring を使ってmodを書きます。このスキルは、今使っているClaude Codeのバージョンでどのイベント・APIが使えるか、modをどこに保存すべきかを知っています。スキルを自分で有効にしたいなら、セッションで /plugin-authoringを入力してください。

進め方は次のとおりです。

  1. 作成場所 : Claudeは ~/.claude/dev-mods/<이 세션의 ID>/<mod 이름>/ にファイルを書きます。 default·acceptEdits 権限モードでは ~/.claudeが保護されたパスなので、ファイルを1つ保存するたびに承認を尋ねます。
  2. ホットリロードの承認 : 最初のファイルを保存すると「このセッションでホットリロードを有効にするか」を尋ねます。 今回のセッションだけ有効にする を選ぶと、このセッションの dev-mods フォルダーにあるmodはターンが終わるときに読み込まれ、ファイルが変わったターンが終わるたびに再読み込みされます。この選択はセッションを再開しても維持されます。 今はしないを選ぶと、ファイルはそのまま残りますが、次にそのセッションを再開するときに読み込まれます。
  3. 読み込み確認: /plugin → Installed タブでmodが見えるか確認し、ここでオフにすることもできます。
  4. 使って直す: 思うようにいかなければ、何を変えたいかをClaudeに伝えればOKです。ファイルを変えたターンが終われば、すぐに次の試行ができます。

一部のセッションでは、Claudeが書いたmodがまったく読み込まれません: 承認してくれる人がいない claude -p 実行や dontAsk モード、まだ信頼（trust）していないワークスペース、 --safe-mode·--bare·disableAllHooksか、組織ポリシーでmod自体がオフになっている場合です。

modを使い続けたいなら: dev-mods フォルダーはそのセッションを作ったセッション専用で、 cleanupPeriodDays（デフォルト30日）が過ぎると自動で消えます。使い続けるには、フォルダーを自分が管理する場所へコピーしてください。

cp -r ~/.claude/dev-mods/<세션 ID>/git-branch ~/mods/git-branch

コピーした後は 自分で作る で説明する --plugin-dirで読み込むか、他の人と使うならマーケットプレイスとして公開すればOKです。

自分で作る

コードがどう動くかを学びたいなら、自分で書いてみるのが一番速いです。Node.jsもバンドラーもなしで、Claude Codeが .ts·.js ファイルを直接読みます。

ここでは tool-tally というmodを作ります。ツールを使うたびに数えて、スピナーの横に · 도구 3번 のように表示し、 /tallyを入力すると、これまで数えた回数を教えてくれます。

1. ファイルを3つ作る

mkdir -p tool-tally/.claude-plugin tool-tally/hooks

tool-tally/.claude-plugin/plugin.jsonはプラグインのマニフェスト（manifest）です。

{
  "name": "tool-tally",
  "version": "0.1.0",
  "description": "도구 호출 수를 세어 스피너 옆에 보여주고 /tally로 알려줘요",
  "author": { "name": "당신의 이름" }
}

tool-tally/hooks/hooks.json はコードファイルがどこにあるかを教えます。この modules キーがないとプラグインはmodになりません。 

{
  "modules": ["./register.ts"]
}

2. コードを書く

tool-tally/hooks/register.tsがフックモジュール（hooks module ）です。 register 関数をエクスポートすると、Claude Codeがmodを読み込むときに一度呼びます。 

import type { On } from 'claude-code'

// 횟수. 아래 두 훅이 같이 써요
let calls = 0

export function register(on: On): void {
  // 세션이 시작할 때 한 번: /tally 명령을 등록해요
  on('session.start', async ($, e, next) => {
    await $.command.register({ name: 'tally', description: '지금까지 쓴 도구 횟수 보기' })
    return next(e)
  })

  // Claude가 도구를 쓰려고 할 때마다
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render') // 화면을 다시 그려서 새 숫자가 보이게 해요
    return next(e) // 도구는 평소대로 실행
  })

  // /tally를 입력했을 때만
  on('command.run', { command: 'tally' }, async () => {
    return { text: '지금까지 도구를 ' + calls + '번 썼어요' }
  })

  // 스피너를 그릴 때마다
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ' · 도구 ' + calls + '번' } })
  })
}

4つのフックがやることです。

  • session.start : セッションの最初のターンの前に一度、そしてモジュールがリロードされるたびに実行されます。 /tally コマンドを追加します。
  • tool.call: Claudeがツールを使う直前に毎回実行されます。回数を増やし、画面を再描画するよう要求します。
  • command.run: /tally を入力したときだけ実行されます。 nextを呼ばずにすぐ答える「応答（answer）」という方式です。
  • ui.render: スピナーを描くたびに実行されます。Claude Codeのスピナーはそのままにし、単語の後ろに回数だけを付ける「変形（rewrite）」という方式です。

3. 読み込んで使ってみる

--plugin-dirはインストールせず、今回のセッションだけプラグインディレクトリを読み込みます。

claude --plugin-dir ./tool-tally

何かツールを数回使わせてみると（여기 파일 목록 보여주고 README 읽어줘 など）スピナーの文言が Thinking · 도구 2번… のように変わります。終わったら /tally を入力して tool-tally: 지금까지 도구를 2번 썼어요が出るか確認してください。

セッションを開いたまま register.ts の ' · 도구 ' を ' · 지금까지 ' に変えて保存してみてください。保存するとトランスクリプトに tool-tally reloadedという行が出て、次のスピナーからすぐに新しい文言が見えます。これがホットリロードです。

4. 型宣言とvalidate

--plugin-dir でmodを読み込むかリロードするたびに、Claude Codeは自分が使っているバージョンに正確に合う型宣言を tool-tally/.claude-plugin/types/ の下に書いてくれます。

パス 含まれる内容
claude-code/index.d.ts すべてのイベントと入出力、すべてのmod APIメソッド、各画面が描ける要素
claude-code-tools/index.d.ts 組み込みツールの入力・結果の型（e.tool === 'Bash'に絞って使えるように）
claude-code-mcp/index.d.ts 最後に保存した時点で接続されていたMCPツールの入力型
tsconfig.json フックモジュールに合わせたコンパイルオプション

エディターの自動補完と型チェックがこれらのファイルを参照します。バージョンごとにイベント・APIが変わりうるので、この生成されたファイルが他のどのドキュメントよりも正確です。

claude plugin validateはセッションを起動せずに、Claude Codeが自分のmodをどう読むかを表示します。

claude plugin validate ./tool-tally
  ❯ ./register.ts hooks: session.start, tool.call, command.run{command=tally}, ui.render{component=Spinner}
  ❯ ./register.ts calls: $.command.register, $.ui.invalidate

✔ Validation passed

hooks: の行は、このモジュールが受け取るイベントをマッチャー（matcher）とともに表示します。意図したイベントがこの行になければ（たいていイベント名の打ち間違い）、そのフックは実行されません。 calls: の行は、このモジュールが呼ぶmod APIをすべて表示します。k-modsに公開するmodは scripts/check.sh mods/<이름> で --strict validateとテストを一度に実行します。

5. 静的解析のルール

Claude Codeはコードを実行しなくても、どのイベントを受け取りどのAPIを呼ぶかを読み取ります。そのためにはコードがいくつかのルールを守る必要があります。破ると claude plugin validateがエラーを出します。

  • $.네임스페이스.메서드(...)を最後まで展開して書く: const ui = $.ui のように変数に入れるか、分割代入するか、 $[name] のように計算された名前でアクセスしてはいけません。 $.ui を変数に入れると $.ui is used as a valueで失敗します。
  • $を渡すヘルパー関数は、同じファイルの最上位で宣言した関数だけが : クロージャ、メソッド、別のファイルから取り込んだ関数には $を渡せません。（$.state の read·updateは例外です。）
  • イベント名は文字列リテラル: on('tool.call', ...)のように直接書く必要があります。変数やループでイベント名を回すと失敗します。
  • 同じイベントをマッチャーなしで2回登録しない: session.startのようにマッチャーのないイベントは、1つのモジュールに1回だけ登録します。
  • register の中で onという名前を再宣言しない : 変数やパラメータで on を隠すと "on" is declared again (shadowed)で失敗します。
  • importはプラグイン内の相対パスと claude-codeだけ : 動的 import() や requireは使えません。すべてのファイルはESモジュールです。
  • Node API・グローバル fetch·setTimeout なし : ファイルは $.fs 、ネットワークは $.http 、タイマーは $.clockを使います。
  • （k-modsの追加ルール）ツール呼び出しをブロックできるフックには .catch 付ける : tool.call, tool.check, prompt.submit のようにチェーンを断ち切れるフックが失敗したらどうするか .catch で決めないと --strict validateを通ります。ブロックする役割のmodなら、失敗したときもブロックする側で答えてください（fail closed）。

6. テストを書く

claude plugin test はセッションもログインもネットワークもなしでフックをテストします。 claude-code/testingからテストツールを取り込みます。

tool-tally/tests/tool-tally.test.ts:

import { expect, test } from 'claude-code/testing'

test('/tally는 지금까지 받은 도구 호출 수를 보고해요', async ($, on) => {
  // Claude Code 대신 도구 호출에 답해 줘요 (실제 도구는 실행 안 됨)
  on('tool.call', () => ({ result: 'ok' }))

  await $.tool.call({ tool: 'Bash', command: 'ls' })
  await $.tool.call({ tool: 'Read', file_path: 'README.md' })

  const answer = await $.command.run({ command: 'tally', args: '' })
  expect(answer.text).toBe('지금까지 도구를 2번 썼어요')
})
claude plugin test

tool-tally ディレクトリで実行すると、テスト名と合否が出ます。k-modsに公開するmodは、純粋なロジック（分類、フォーマット変換など）を $ を受け取らない関数に切り出して通常の単体テストで検証し、イベントのやり取りの流れだけを claude plugin testで確認することをおすすめします。

7. 状態の保存: 変数 vs state vs store

値をどこに置くかによって、どれだけ長く残るかが変わります。

保存場所 残る期間 こんなときに使います
モジュール変数（let calls = 0) モジュールがリロードされるまで（開発中に保存するたびリセット） 失ってもよい値。このチュートリアルの callsのように
$.state セッションが終わるか、 /clear·/resume·/branchをするまで。リロードにも耐えます。 画面が依存する値だが、リロードには耐える必要があるとき。値を書き込むと、その値を読む画面が自動で再描画されます（リアクティブ）。
$.store 自分が削除するか、 cleanupPeriodDays の間、どのセッションも使わなくなるまで 設定値・記録のように、次にセッションを開いても残っているべき値。このコンピューターのすべてのセッションが1つを共有します。

3つを混ぜて使うこともよくあります。詳しいコード例（$.state に型宣言する、 /clear 以降の値の復元など）は公式ドキュメントにあります。

k-modsに公開する

modができたらk-modsカタログに公開できます。コードを直接書かなくてよい方法と、自分で登録する方法の2つです。

  • 良いmodを知っているなら : コードを知らなくても modを推薦する Issueを残せばOKです。
  • 自分で登録したいなら: registry/<이름>.json ファイルを1つ追加するPRを送ってください。自動チェックがインストール・静的解析・ライセンスを確認します。

どちらの経路も、詳しい手順とルールは コントリビュートガイドにあります。
