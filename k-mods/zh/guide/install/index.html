安装指南

k-mods 是普通的 Claude Code 插件市场。所以安装、更新、卸载全都通过 Claude Code 的 /plugin 命令与 claude plugin 用 shell 命令完成。本文按顺序整理从检查版本、添加市场、安装范围 (scope)、与团队成员共用，到问题排查。

检查版本

mod 要加载需要最低版本。

  • 终端 ：Claude Code 2.1.287 及以上。在 shell 中 claude --version来确认。
  • 桌面应用 ：2.1.286 及以上。在 Code 标签页中 /status 输入后会 Claude Code 行会显示版本。

版本过低时，请更新 Claude Code 或桌面应用后重试。

官方文档： Turn mods on or off

添加市场

安装 k-mods 前需要先注册一次市场。在会话里做也行，在 shell 里做也行。

在会话内

/plugin marketplace add dogebi/k-mods

在 shell 中 （不打开会话，在脚本等中使用） 

claude plugin marketplace add dogebi/k-mods

成功后 Successfully added marketplace: k-mods 会出现。市场名称不是仓库名，而是 marketplace.json 的 name 字段里来，而 k-mods 两者相同。之后 <mod 이름>@k-mods 的形式安装。

官方文档： Add a marketplace

安装

在会话内

/plugin install starter@k-mods

在会话中 /plugin install 不会直接安装，而是先 /plugin 面板会显示该 mod 的详细信息（说明、新增的命令与钩子、权限）。在那里选安装范围，才会在那一刻安装。

在 shell 中 （立即安装） 

claude plugin install starter@k-mods

k-mods 也预先打包了一些组合。

  • starter@k-mods：推荐组合。README“先试试这些”里的 mod（ko-ui、skins、pixel-pals、ctx-strip、mod-store）会一次装好。
  • korean-pack@k-mods：只装韩语包（菜单、设置、任务栏翻译，ko-ui）。

想逐个挑着装的话 mod-store@k-mods 装上之后，在会话中 /k-mods。目录会以面板打开，可以用按钮安装和删除。

官方文档： Install a plugin

安装范围 (scope)

安装时从三个范围中选一个。范围决定了“谁拿到这个 mod”和“记录到哪个设置文件”。

范围 谁能拿到 被记录的文件
user（用户） 在这台电脑的所有项目里，只有我 ~/.claude/settings.json
project（项目） 在这个仓库里工作的所有人 .claude/settings.json （会提交的文件）
local（本地） 只在这个仓库里，我 .claude/settings.local.json （通常不提交）

在 shell 中 --scope user|project|local 来选择，省略时 user。

claude plugin install blast-radius-ko@k-mods --scope project

同一个 mod 同时在多个范围设置时 local > project > user 的顺序优先。比如只想自己关掉项目开启的 mod，在 local 范围关掉即可。

官方文档： Choose an install scope

关闭、删除

在会话内: /plugin → Installed 在标签页里选中条目后 Disable plugin, Uninstall 会出现相同的菜单。 /plugin enable <mod>@k-mods, /plugin disable <mod>@k-mods, /plugin uninstall <mod>@k-mods也能直接打开。

在 shell 中

claude plugin disable blast-radius-ko@k-mods
claude plugin enable blast-radius-ko@k-mods
claude plugin uninstall blast-radius-ko@k-mods --scope project

enable·disable--scope 省略时，会自动找出该 mod 已设置的范围。 uninstall 省略时 user 里删掉这个范围。

项目开启的 mod Uninstall 就会问“只关掉我这边，还是从整体中移除”。只想自己关掉就 .claude/settings.local.json 在 false 的写法（默认键 y)，若要从整体中移除，就选直接改共享文件的方式（u)，选择这个即可。

官方文档： Manage installed plugins

立即应用到会话

在 shell 中安装、更新或删除过，或者 /plugin 如果在面板外改了设置文件，已打开的会话不会自动反映。请在会话里这样输入。 

/reload-plugins

/plugin 关闭面板时如果有改动，Claude Code 会自动 /reload-plugins 。但如果这次重载可能破坏提示缓存（例如增删 MCP 服务器时），就不会立即应用，只给警告。那种情况下 /reload-plugins --force强制应用，不过接下来的一个请求会不经缓存处理，成本更高。

官方文档： /reload-plugins

查看已安装的 mod

在会话内 /plugin 输入后，标签页下方会以浅色文字 N mods active · 이름1, 이름2 的形式出现。这一行里 不包含内置 mod。 装了却在这一行看不到名字，就是加载失败。

在 shell 里能看得更详细。

claude plugin list
claude plugin details mod-store

plugin list 会显示版本、范围、状态， plugin details会显示该 mod 新增的命令、钩子、智能体列表，以及上下文开销。

官方文档： See which mods a session loaded

填入设置值 (userConfig)

有些 mod 安装时会追问额外值（API 地址、令牌等）。这些值存在插件的 userConfig声明的。

  • 安装与激活时机：值为空时，设置对话框会自动弹出。
  • 稍后重新打开 ：在会话中 /plugin configure <mod>@k-mods。
  • 一眼看懂 ：Claude Code 2.1.269 及以上时 /config 面板里每个已激活的 mod 都有一行设置。不过敏感值（ sensitive）或可选择多个的值（multiple ) 则 /config里看不到。
  • 在 shell 中填入值 ：安装时 --config key=value，或者在安装后像下面这样把 JSON 从标准输入传进去。
echo '{"api_url": "https://example.com"}' | claude plugin configure my-mod@k-mods --values-stdin

敏感值会 settings.json，而是保存到操作系统的安全存储（macOS 钥匙串等）。

官方文档： User configuration

保持最新版本

每个市场的自动更新默认值不同。

  • 默认开启：Anthropic 官方市场的大部分
  • 默认关闭：包括 k-mods 在内的其他所有市场

k-mods 默认关闭自动更新，想拿到最新审查和修复，请偶尔执行下面任一操作。

  • 在会话中开启自动更新: /plugin → Marketplaces 标签页 → k-mods 选择 → Enable auto-update

  • 只刷新市场目录 （确认是否新增 mod，已安装的 mod 保持不变） 

    claude plugin marketplace update k-mods

  • 连同已安装的 mod 一起更新 ：在会话中 /plugin → Marketplaces 标签页 → k-mods 选择 → Update marketplace

  • 只更新一个 mod

    claude plugin update starter@k-mods

官方文档： Keep plugins updated

与团队成员共用

把设置提交到仓库里，打开该仓库的所有成员都会自动注册 k-mods 市场，并以“已开启”状态启动指定的 mod。 .claude/settings.json里这样写，然后提交。

{
  "extraKnownMarketplaces": {
    "k-mods": {
      "source": { "source": "github", "repo": "dogebi/k-mods" }
    }
  },
  "enabledPlugins": {
    "starter@k-mods": true
  }
}

在 shell 里运行一次，这个文件就会自动生成。

claude plugin marketplace add dogebi/k-mods --scope project
claude plugin install starter@k-mods --scope project

注意点: enabledPlugins里写的 mod 只是变成“已开启”状态，不会自动下载到团队成员的电脑。新拿到仓库的每位成员都要执行一次下面的命令才会真正装上（在信任（trust）工作区之后）。

claude plugin install starter@k-mods --scope project

跳过这一步，Claude Code 会提示“.claude/settings.json开了这个插件但没装”的提示。

官方文档： Register the marketplace for everyone in a repository, extraKnownMarketplaces, enabledPlugins

问题排查清单

mod 装好了却什么都没发生，就从上到下逐项检查。

  1. 版本过低: claude --version 或桌面应用的 /status 确认。 检查版本 参考。

  2. 尚未信任（trust）工作区：需要在这个目录中打开一次交互式会话并接受信任确认窗口，mod 才会加载。

  3. --bare 或 --safe-mode以……开头：这两个 flag 会关闭全部已安装的 mod。请去掉 flag 再启动一次。

  4. disableAllHooks已设置 ：在我的设置文件或组织的 managed settings 中，这个值 true时，装好的 mod 会全部关闭。

  5. 被组织策略阻止 ：管理员 allowManagedModsOnly 开启后，只加载组织分发的 mod。详见 安全指南里。

  6. /plugin的“N mods active”行里没有名字 ：装是装上了，但加载失败。 claude plugin validate <경로>先确认，或看下面的调试日志。

  7. 查看调试日志：在 shell 里这样运行，日志中会留下一行说明为什么没出现。

    claude --debug-file ./mod-debug.log --plugin-dir ./문제의-mod
tail -f ./mod-debug.log | grep 문제의-mod
