做一个自己的 mod

制作 mod 有两种方式：用自然语言让 Claude 来做，或者自己写代码。本文两种方式都讲，最后再接到把做好的 mod 发布到 k-mods 的流程。

让 Claude 来做

这是最快的办法。在会话里把想要的直接说出来就行。

입력창 위에 현재 git 브랜치를 보여주는 mod 만들어 줘

Claude 会用内置技能 plugin-authoring 来写 mod。这个技能知道你现在用的 Claude Code 版本能用哪些事件和 API、mod 该存在哪里。想直接打开这个技能，就在会话里 /plugin-authoring。

流程是这样的。

  1. 编写位置 ：Claude ~/.claude/dev-mods/<이 세션의 ID>/<mod 이름>/ 里写文件。 default·acceptEdits 在权限模式下 ~/.claude是受保护的路径，每保存一个文件都会问是否批准。
  2. 批准热重载 ：保存第一个文件时会问“要不要在这个会话里开启热重载”。 仅本次会话开启 选中后，本会话的 dev-mods 文件夹里的 mod 会在回合结束时加载，文件有改动的回合结束后又会重新加载。这个选择在恢复会话后也保留。 暂不选中后文件会留着，但下次重启该会话时才加载。
  3. 确认加载: /plugin → Installed 标签页里看 mod 有没有显示，也可以在这里关掉。
  4. 试用并修改：没达到想要的效果，就直接告诉 Claude 要改什么。改了文件的回合一结束，就能马上试下一次。

有些会话里 Claude 写的 mod 根本不加载：没有能批准的人的 claude -p 运行或 dontAsk 模式、还没信任（trust）的工作区， --safe-mode·--bare·disableAllHooks或组织策略把 mod 本身关掉的情况。

想继续用这个 mod 的话: dev-mods 文件夹是给创建那个会话的人专用的，而 cleanupPeriodDays（默认 30 天）过了会自动删除。想继续用，就把文件夹复制到我管理的位置。

cp -r ~/.claude/dev-mods/<세션 ID>/git-branch ~/mods/git-branch

复制之后 自己动手做 里说的 --plugin-dir加载，想和别人一起用就公开成市场。

自己动手做

想弄懂代码怎么跑，直接写一遍最快。不需要 Node.js 或打包器，Claude Code 会 .ts·.js 会直接读文件。

这里 tool-tally 的 mod。每次用工具就计数，并在 spinner 旁边 · 도구 3번 那样显示， /tally，就会告诉你到现在为止计的次数。

1. 建三个文件

mkdir -p tool-tally/.claude-plugin tool-tally/hooks

tool-tally/.claude-plugin/plugin.json是插件的清单（manifest）。

{
  "name": "tool-tally",
  "version": "0.1.0",
  "description": "도구 호출 수를 세어 스피너 옆에 보여주고 /tally로 알려줘요",
  "author": { "name": "당신의 이름" }
}

tool-tally/hooks/hooks.json 会告诉我代码文件在哪里。这个 modules 键，插件才能成为 mod。 

{
  "modules": ["./register.ts"]
}

2. 写代码

tool-tally/hooks/register.ts是钩子模块（hooks module ）。 register 导出函数后，Claude Code 加载 mod 时会调用一次。 

import type { On } from 'claude-code'

// 횟수. 아래 두 훅이 같이 써요
let calls = 0

export function register(on: On): void {
  // 세션이 시작할 때 한 번: /tally 명령을 등록해요
  on('session.start', async ($, e, next) => {
    await $.command.register({ name: 'tally', description: '지금까지 쓴 도구 횟수 보기' })
    return next(e)
  })

  // Claude가 도구를 쓰려고 할 때마다
  on('tool.call', async ($, e, next) => {
    calls += 1
    $.ui.invalidate('ui.render') // 화면을 다시 그려서 새 숫자가 보이게 해요
    return next(e) // 도구는 평소대로 실행
  })

  // /tally를 입력했을 때만
  on('command.run', { command: 'tally' }, async () => {
    return { text: '지금까지 도구를 ' + calls + '번 썼어요' }
  })

  // 스피너를 그릴 때마다
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ' · 도구 ' + calls + '번' } })
  })
}

就是这四个钩子做的事。

  • session.start ：会话第一回合前执行一次，之后每次模块重载都会执行。 /tally 命令。
  • tool.call：Claude 每次用工具前都会执行。把次数加一，并请求重绘界面。
  • command.run: /tally 时才会执行。 next不调用……直接回答的“响应（answer”的方式。
  • ui.render：每次绘制 spinner 时执行。Claude Code 的 spinner 原样保留，只在词后面加上次数的“变体（rewrite”的方式。

3. 加载来试用

--plugin-dir不安装，只在本次会话里加载插件目录。

claude --plugin-dir ./tool-tally

让它用几次工具后（여기 파일 목록 보여주고 README 읽어줘 等）spinner 文案会 Thinking · 도구 2번… 那样变。结束后 /tally 输入 tool-tally: 지금까지 도구를 2번 썼어요有没有出现。

开着会话不动 register.ts 的 ' · 도구 '' · 지금까지 ' 改掉再保存试试。保存后，转录里会出现 tool-tally 会出现 reloaded 一行，下一个 spinner 起就能看到新文案。这就是热重载。

4. 类型声明与 validate

--plugin-dir 加载或重载 mod 时，Claude Code 都会生成与我用的版本完全对应的类型声明 tool-tally/.claude-plugin/types/ 写在下面。

路径 包含的内容
claude-code/index.d.ts 所有事件与输入输出、所有 mod API 方法、各界面能画的元素
claude-code-tools/index.d.ts 内置工具的输入与结果类型（e.tool === 'Bash'来收窄使用范围）
claude-code-mcp/index.d.ts 最近保存时已连接的 MCP 工具的输入类型
tsconfig.json 适配钩子模块的编译选项

编辑器的自动补全和类型检查会看这些文件。每个版本的事件与 API 都可能变，所以这些生成的文件比其他任何文档都准确。

claude plugin validate不用起会话，就能看到 Claude Code 是怎么读我的 mod 的。

claude plugin validate ./tool-tally
  ❯ ./register.ts hooks: session.start, tool.call, command.run{command=tally}, ui.render{component=Spinner}
  ❯ ./register.ts calls: $.command.register, $.ui.invalidate

✔ Validation passed

hooks: 行会显示这个模块接的事件和 matcher。想要的事件不在这行里（通常是事件名打错），那个钩子就不会执行。 calls: 行会显示这个模块调用的全部 mod API。要上架到 k-mods 的 mod scripts/check.sh mods/<이름> 以 --strict 一次跑完 validate 和测试。

5. 静态分析规则

Claude Code 不执行代码也能读出会接哪些事件、调哪些 API。为此代码必须守几条规则。违反了 claude plugin validate会报错。

  • $.네임스페이스.메서드(...)完整展开写出: const ui = $.ui 那样放进变量、解构，或 $[name] 那样用算出来的名字访问是不行的。 $.ui 放进变量时 $.ui is used as a value而失败。
  • $的辅助函数，只能是同一文件顶层声明的函数 ：闭包、方法、从其他文件导入的函数上 $无法传入。（$.state 的 read·update是例外。）
  • 事件名要用字符串字面量: on('tool.call', ...)那样直接写。用变量或循环传事件名会失败。
  • 同一事件不要在没有 matcher 的情况下注册两次: session.start那样没有 matcher 的事件，一个模块只注册一次。
  • register 在内 on不要重复声明叫……的名字 ：用变量或参数 on 指到……时 "on" is declared again (shadowed)而失败。
  • import 只认插件内的相对路径和 claude-code仅 ：动态 import() 或 require不行。所有文件都是 ES 模块。
  • Node API、全局 fetch·setTimeout 无 ：文件是 $.fs ，网络是 $.http ，定时器是 $.clock。
  • （k-mods 附加规则）能拦截工具调用的钩子上 .catch 添加 : tool.call, tool.check, prompt.submit 那样能切断链条的钩子失败时怎么办 .catch 来定 --strict 通过 validate。如果是负责拦截的 mod，失败时也要按拦截来回答（fail closed）。

官方文档： Follow these rules so that static analysis can find every hook and call

6. 写测试

claude plugin test 不用会话、不用登录、不用网络就能测钩子。 claude-code/testing里导入测试工具。

tool-tally/tests/tool-tally.test.ts:

import { expect, test } from 'claude-code/testing'

test('/tally는 지금까지 받은 도구 호출 수를 보고해요', async ($, on) => {
  // Claude Code 대신 도구 호출에 답해 줘요 (실제 도구는 실행 안 됨)
  on('tool.call', () => ({ result: 'ok' }))

  await $.tool.call({ tool: 'Bash', command: 'ls' })
  await $.tool.call({ tool: 'Read', file_path: 'README.md' })

  const answer = await $.command.run({ command: 'tally', args: '' })
  expect(answer.text).toBe('지금까지 도구를 2번 썼어요')
})
claude plugin test

tool-tally 目录里运行，就会显示测试名和是否通过。要上架到 k-mods 的 mod，最好把纯逻辑（分类、格式转换等） $ 抽成不接这个参数的函数，用普通单元测试验证，只有事件往来的流程 claude plugin test来确认。

7. 状态保存：变量 vs state vs store

值放在哪里，决定了它能存活多久。

保存位置 存活时间 适用场景
模块变量（let calls = 0) 直到模块重载为止（开发中每次保存都会重置） 丢了也没关系的值。本教程的 calls如
$.state 会话结束或 /clear·/resume·/branch为止。重载后也还在。 界面依赖这个值，但又要熬过重载时。写入值后，读这个值的界面会自动重绘（响应式）。
$.store 我自己删掉，或者 cleanupPeriodDays 期间一直没有会话使用为止 像设置值、记录这类下次开会话也要留下的值。这台电脑的所有会话共用一个。

三种混着用的情况也很多。详细的代码示例（$.state 里声明类型， /clear 之后恢复值等）都在官方文档里。

发布到 k-mods

mod 做好后可以上架到 k-mods 目录。有两条路：不用自己写代码的办法，和自己注册的办法。

  • 如果你知道好的 mod ：即使不懂代码 推荐 mod 留个 issue 就行。
  • 想自己注册的话: registry/<이름>.json 发一个只加一个文件的 PR。自动检查会验证安装、静态分析和许可证。

两条路的详细流程和规则都在 贡献指南里。
